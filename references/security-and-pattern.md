# 桥的形式与安全边界

请求路径：Agent → Skill CLI → 经过身份核验的本机命名管道 → 原应用内包装入口 → 同一个 DS Bot 运行时。回复沿请求编号、消息和轮次回到 CLI。

这是可复用的结构，实际实现只支持本包钉定的 Windows DS Bot 版本。适配其他应用需要重新找出其真实运行时入口、认证边界、任务标识与回复完成条件，不直接套用 DS Bot 接口或其他 Bot 登录态。

## 为什么放在原运行时里

原 HTTP `/api/bot` 需要其启动认证，外部 CLI 没有现成的安全凭据交接。本桥不提取 Cookie，新增经过批准的本机 owner 通道。原未认证 HTTP 仍被拒绝。

包装入口要求原 Loader 条目已禁用且无 fiber，复用其有效配置，调用原 `createRuntime` 一次。版本、相关源码、前端资源和冷启动标记有固定校验。动态配置不支持时停止，不猜测配置效果。原依赖通过公开安装锚点解析，避免同名包装包的自引用。

## IPC 身份

- 服务端使用当前 Windows **登录会话 SID** 的保护 DACL，拒绝远程连接、要求首个管道实例，句柄不继承。
- 客户端采用匿名模拟级别，在同一连接句柄上核对服务端 PID 与可执行文件后，才通过匿名标准输入提供请求。
- 每次启动随机管道名；端点文件只含实例、管道名和 helper PID。没有 bearer token。helper 随原应用生命周期退出。
- 同一登录会话内其他本机进程属于信任范围，不是 Dot／Codex 独占身份。不同用户、低完整性或安全策略拦截不得绕过。

## 操作和数据范围

只暴露 `capabilities`、受白名单约束的 `send` 和已有收据绑定的 `query`。私有 Fetch 路由还要求单次真实 Request 对象身份与专用 owner peer；普通 HTTP、复制请求和重放不能获得这个身份。维护门控继续生效。

不提供通用 RPC、Bot 管理、群管理、文件读取、Shell 或工具执行。发送时固定稳定 Bot ID 和当前会话，最后提交前再次核对，拒绝静默转到新会话。

只读会话观察使用公开的非激活观察接口，读取一致的事件／投影视图并释放观察。只选取匹配回执的普通回复文本，排除思考和工具正文。默认发现和历史输出是元数据；显式选择的会话才可展开文本。

## 防重发和回复关联

| 阶段 | 保证 |
| --- | --- |
| 预览 | 不发消息、不写收据；哈希绑定实例、目标、会话、完整文本与请求编号 |
| 只读前置探测 | 单次、有界；失败时尚无发送意图，明确标记未提交 |
| 提交前 | CLI 与桥端分别排他创建并 fsync 意图；已有 ID 不再次派发 |
| 已接受／超时 | 保留原编号，只查询或续等，未知结果不自动重试 |
| 回复完成 | 匹配原 rpcId、正文哈希、唯一用户锚点与正常 turn/end；冲突不判成功 |
| 业务验收 | 回复完成与用户任务验收分别记录，不把 Bot 声明当执行证据 |

收据只保存哈希、状态、序号和关联元数据，不保存正文。常见凭证格式会掩码，但不能依赖它承载密钥；不主动读取或发送凭证。

边界不涵盖同登录会话恶意进程、恶意内核或管理员。未进行跨用户／远程攻击实验，不能据配置推断所有攻击已验证。原实例升级后须重新审阅钉定接口，不放宽校验来恢复运行。

本包不包含常驻 DS Bot → Agent 执行器。它提供 Agent 发请求、再取回复的协作通道；消息内容始终不授予新的工具或外发权限。
